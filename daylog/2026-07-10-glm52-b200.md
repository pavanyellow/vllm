# 2026-07-10 — GLM-5.2-FP8 on 8×B200: setup + smoke test

Goal: characterize cold TTFT for the voice workload (C=1, 3–5k token prompts) on
`zai-org/GLM-5.2-FP8` (743B MoE / 39B active, MLA + DSA sparse attention, 78 layers,
256 experts top-8, MTP-5). Same method as the Qwen3.6 study (see daylog README).

Theory (done previously, not re-derived here): weight-read floor at 4k ≈ 12 ms
(750 GB FP8 ÷ 64 TB/s), honest floor ≈ **20 ms** (11.3 expert read + ~4.5 attn/dense
compute + 2–3 comms + ~2 dispatch). Expected recipe-verbatim ≈ 100–200 ms (78-layer
eager dispatch); tuned target ~40–60 ms cold / ~25 ms warm.

## E0 — recipe-verbatim smoke test

(pending download + install)

Launch:

```bash
vllm serve zai-org/GLM-5.2-FP8 --served-model-name glm-5.2-fp8 \
  --host 0.0.0.0 --port 8080 --tensor-parallel-size 8 --kv-cache-dtype fp8_e4m3 \
  --max-model-len 32768 --gpu-memory-utilization 0.85 \
  --max-num-batched-tokens 8192 --max-num-seqs 32 \
  --speculative-config.method mtp --speculative-config.num_speculative_tokens 5 \
  --default-chat-template-kwargs '{"enable_thinking":false}' \
  --reasoning-parser glm45 --tool-call-parser glm47 --enable-auto-tool-choice
```

(thinking OFF is mandatory for voice — GLM defaults to Think Max ≈ 10 s to first content)

Deltas vs the official recipe (recipes.vllm.ai/zai-org/GLM-5.2?hardware=b200),
all deliberate: recipe sets `VLLM_DEEP_GEMM_WARMUP=skip` (faster startup, first
requests JIT instead) — we keep warmup ON so measurements never pay compile;
we add `--max-model-len 32768` (voice path; recipe targets 1M ctx),
`--gpu-memory-utilization 0.85`, `--max-num-batched-tokens 8192`, and the
thinking-off template kwargs. Rest is recipe-verbatim (TP8, fp8_e4m3 KV, MTP-5,
max-num-seqs 32, glm45/glm47 parsers).

**Attempt 1 failed at +16 min**: FlashInfer JIT (`trtllm_fused_moe_kernel_launcher.cu`,
compiled during warmup) died with `fatal error: nvrtc.h: No such file or directory` —
the third instance of the same image gap (missing CUDA dev headers). Durable fix
instead of per-process env: symlinked all 50 headers present in the torch nvidia
wheel (`site-packages/nvidia/cu13/include/*.h`) but absent from
`/usr/local/cuda/include`. Attempt 1 timings still valid and recorded below;
attempt 2 relaunched 21:47 PT (torch.compile AOT cache now warm, ~220 s saved).

Startup log details (v0.23.0, V1 engine, arch `GlmMoeDsaForCausalLM`):

- Attention: **FLASHINFER_MLA_SPARSE** (only candidate), HND KV layout,
  **FLASH_ATTN MLA prefill** backend.
- KV cache: standard fp8 format; log hints DeepSeek `fp8_ds_mla` format is available
  via `--attention-backend FLASHMLA_SPARSE` → candidate experiment lever.
- MoE FP8 backend: **FLASHINFER_TRTLLM** auto-selected (DEEPGEMM built and available
  but not chosen out of ['AITER', 'FLASHINFER_TRTLLM', 'FLASHINFER_CUTLASS',
  'DEEPGEMM', 'TRITON', ...]) → backend A/B is a candidate experiment.
- Dense FP8 linear: **DeepGemmFp8BlockScaledMMKernel** (DeepGEMM E8M0 enabled) —
  so DeepGEMM serves the dense path while FlashInfer TRTLLM serves MoE.
- All-reduce tp group: CUSTOM → SYMM_MEM → PYNCCL dispatch order; ep group PYNCCL only.
- Parallelism: pure TP8 (pp=1, dp=1, no EP) — each GPU holds a 1/8 slice of all
  256 experts. TP8+EP is E4.
- Weight load: 141 shards, **91.0 GiB/GPU, 73.5 s** (page-cache-fed; 2.8 TB RAM box).
- torch.compile: 221.8 s cold, AOT cache saved to /workspace/.vllm_cache.

- DSA indexer: **DEEPSEEK_V32_INDEXER** backend, KV block size 64.
- GPU KV cache: **1,071,360 tokens** (fp8_e4m3, max-model-len 32768, gpu-util 0.85).
- Stock cudagraph ladder: **PIECEWISE 41 sizes (largest 384), FULL 25 (largest 192)**
  → prompts >384 tokens prefill outside graphs in stock config; E3 attacks this.
- Attempt-2 startup (warm caches): weights ~73 s, compile ~0 (AOT hit), MoE JIT
  compiled clean after header fix.

## E1 — baseline TTFT curve

Grid: 1000, 1900, 2048, 2200, 3000, 3500, 4000, 4096, 4500, 5000, 6000, 7000,
8000, 8192, 8500. Client `ttft_sweep.py` (C=1, p50 of 8+, discard 4 warmup;
GLM vocab 154,880 → default id range 100–150000 OK).

Hypothesis: smooth curve (no mamba → no 1056 sawtooth); watch L=2048 (DSA top-k
boundary) and 8192 (chunk edge).

```
   8000        357.6        358.3        356.7

```

Reading:

- **Voice band (3–5k): 208–240 ms p50.** Slightly above the expected 100–200 ms
  recipe-verbatim range; 10–12× the ~20 ms honest floor.
- **Flat plateau ~200–210 ms from 1000 to 4096** → fixed cost dominates, not
  compute. Consistent with the 78-layer eager-dispatch-bubble hypothesis: stock
  cudagraphs top out at 384 (piecewise) / 192 (full) tokens, so every prefill in
  our band runs eager. E3 (graph ladder to 8192) is the direct attack.
- **Smooth curve, no sawtooth** — Qwen's 1056 artifact was mamba-specific,
  confirmed absent. No anomaly at the 2048 DSA boundary (198.6 ms is the curve
  minimum) or at 4096.
- Compute becomes visible above ~4.5k: linear ~+40 ms/1k tokens from 4500→8192.
- **+41 ms step 8192→8500**: crossing max-num-batched-tokens=8192 → second
  chunked-prefill pass. Same shape as Qwen's chunk-edge effect, at the expected
  location.
- p90≈p50 nearly everywhere (tight; C=1 dedicated box). The 1000-token p90
  (216 vs 202) is the only wobble — first post-warmup rounds.
