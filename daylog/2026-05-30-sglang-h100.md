# 2026-05-30 (SGLang, H100)

Companion to `2026-05-30-h100.md` (vLLM E8–E12). Same box, same model, same
`ttft_sweep.py`, same C=1 3k–5k serving path — swap the engine to **SGLang** and
re-measure for a head-to-head. vLLM numbers below are quoted from E8 (stock,
attn block 1056) and E9 (`--block-size 8192`, the sawtooth fix).

## Method
- Same E-style: command + conditions, not claims. Reuse `ttft_sweep.py` unchanged
  (raw random token-ids → /v1/completions, 0% prefix-cache, TTFT = send→first chunk).
- Apples-to-apples: identical client, lengths, n/warm; only the server differs.
- Understand before fixing.

## Setup
- Served `Qwen/Qwen3.6-35B-A3B-FP8` (as `Qwen/Qwen3.6-35B-A3B`). `/v1/models` → 200,
  raw-token-id completion → 200. Model arch is `Qwen3_5MoeForConditionalGeneration`
  (`model_type=qwen3_5_moe`) — SGLang serves it via `srt/models/qwen3_5.py` (0.5.12 only).
- Server: `python -m sglang.launch_server --model-path Qwen/Qwen3.6-35B-A3B-FP8
  --served-model-name Qwen/Qwen3.6-35B-A3B --context-length 32768
  --mem-fraction-static 0.90 --chunked-prefill-size 8192 --reasoning-parser qwen3
  --port 30000`. These mirror vLLM's Setup (32k ctx, 0.90 mem, 8192 chunk).
- Box: H100 80GB SXM, **SGLang 0.5.12.post1**, sglang-kernel 0.4.2.post2+cu130,
  torch 2.11.0+cu130, flashinfer 0.6.11.post1, transformers 5.6.0, CUDA 13.0, py 3.12.
  **Isolated venv** (`/vllm-workspace/sgl-venv`), no vLLM on path. Launch from `/tmp`
  (neutral cwd — same shadowing caveat as vLLM). `nohup &` to persist (the harness
  reaps managed-background GPU trees).
- Backends (auto-picked, H100): full-attn = **fa3** (FlashAttention-3); linear-attn
  (gated-deltanet) = **TritonGDNKernel** (decode+extend); mamba = triton; MoE = auto;
  sampling = flashinfer; grammar = xgrammar. No DeepGEMM JIT phase (vLLM spent ~5 min there).
- Cold start: weights 14.9 s (cached, multi-thread loader), cudagraph capture 25.4 s,
  ready ~3 min. No per-shape FP8-GEMM JIT.
- Memory layout (the key structural diff vs vLLM — separate allocators, **no unified
  mamba==attn page**):
  - weights 34.19 GB; **Mamba cache** 287 slots = 17.28 GB (conv 0.40 + ssm 16.88);
    **KV** 19.20 GB (K 9.60 + V 9.60) → **1,006,799 tok**; avail 7.3 GB.
  - `page_size=1` → attention KV is **not** quantized into a 1056-token block. This is
    the whole story for E-SG2.
  - concurrency cap: `max_running_requests=95` (cudagraph mem), mamba 287 slots.

## E-SG0 — bring-up cost (the real "number" vs vLLM)
vLLM here was `pip`-and-go (E8 just ran). SGLang on this CUDA-13 / torch-2.11 box was
**not**. Logged because "how hard to stand up" is part of the comparison:
- PyPI `sgl-kernel` is a CUDA-12 build (`libnvrtc.so.12`); box is CUDA 13. The cu130
  channel exists at `docs.sglang.ai/whl/cu130` but ships the package under the **new
  name** `sglang-kernel` (0.4.x), not `sgl-kernel` (0.3.x).
- The published `sglang` wheel hard-pins `flash-attn-4>=4.0.0b9` (no wheel → source
  build) + exotic GPU pkgs (tilelang/quack/deep-gemm/cutlass-dsl) the qwen3_5 forward
  path never touches → a bare `pip install sglang` cannot resolve. Installed
  `sglang --no-deps` + the real runtime closure; kernel pinned to `0.4.2.post2+cu130`
  (matches sglang's `==0.4.2.post2`), flashinfer JIT from PyPI, torchvision 0.26+cu130
  (sglang hard-imports `torchvision.io` at load; 0.27 wants torch 2.12 → pin 0.26).
- One torch-ABI trap: `timm`/`torchvision` silently dragged torch 2.12 (breaks cu130
  kernel ABI); pinned torch back to 2.11.0+cu130, dropped the vision-only deps.
- Net: vLLM 1 command; SGLang ~ a dozen, all packaging (not model) friction. Kernel,
  once cu130-matched, loads clean against torch 2.11 (no ABI shim).

## E-SG1 — TTFT sweep 3k–5k, C=1, no cache (vs vLLM E8/E9)
`ttft_sweep.py --url …:30000/v1/completions --model Qwen/Qwen3.6-35B-A3B
--lengths 3000,3168,3500,4000,4096,4224,4500,4752,5000 --concurrency 1 --n 12 --warm 4`.
Same grid + method as vLLM E8.

| in | vLLM E8 p50 (blk 1056) | vLLM E9 p50 (blk 8192) | **SGLang p50** | SGLang p90 |
|---:|---:|---:|---:|---:|
| 3000 | 173.0 | 88.1  | **94.9** | 95.3 |
| 3168 | 93.9  | 93.2  | **95.5** | 96.0 |
| 3500 | 114.5 | 94.6  | **95.3** | 101.0 |
| 4000 | 171.2 | 94.0  | **96.0** | 97.0 |
| 4096 | 173.0 | 94.9  | **95.5** | 97.1 |
| 4224 | 99.5  | 94.9  | **95.3** | 98.2 |
| 4500 | 117.5 | 97.1  | **95.4** | 95.9 |
| 4752 | 179.4 | 99.5  | **95.7** | 96.1 |
| 5000 | 174.8 | 103.3 | **98.5** | 98.7 |

**No sawtooth, no tuning.** SGLang is dead-flat ~95 ms across the whole band; p90
hugs p50 (real). It lands on vLLM's *tuned* E9 fast band — i.e. SGLang's default
already does what vLLM needed `--block-size 8192` to reach. vLLM stock (E8) paid up
to ~1.8× on non-1056-aligned lengths (4752: 179 vs 96); SGLang has no such alignment
sensitivity because `page_size=1` — prompts are never split on a sub-block grid, so
every L ≤ chunk does one 40-layer pass. (vLLM E9 dips to 88 @3000 then rises to 103
@5000 = real compute scaling; SGLang's floor sits ~95 and barely moves over 3k–5k.)

## E-SG2 — prefill scaling across the chunk boundary, C=1
`ttft_sweep.py --lengths 256,1024,2048,4224,8000,8192,8500,12288,16384,24576,32000
--concurrency 1 --n 10 --warm 3`. Locate SGLang's *only* step (the 8192 chunk edge).

| L | p50 ms | p90 | chunks (×8192) | note |
|---:|---:|---:|---:|---|
| 256   | 88.5  | 94.0  | 1 | floor |
| 1024  | 94.7  | 95.6  | 1 | |
| 2048  | 89.5  | 90.5  | 1 | |
| 4224  | 96.0  | 97.0  | 1 | (E8's vLLM-fast point) |
| 8000  | 143.7 | 149.1 | 1 | full single chunk |
| 8192  | 146.5 | 152.3 | 1 | chunk edge |
| 8500  | 229.9 | 230.4 | 2 (8192+308) | **+83 ms = one extra pass** |
| 12288 | 233.7 | 235.6 | 2 (8192+4096) | |
| 16384 | 298.8 | 305.7 | 2 (8192+8192) | ≈ 2×146.5 ✓ |
| 24576 | 474.6 | 483.0 | 3 | |
| 32000 | 649.1 | 654.9 | 4 | |

Single step, at `chunked_prefill_size=8192` only. 8500 jumps to 230 (the 308-tok tail
forces a 2nd ~full 40-layer pass — same chunk-split penalty physics as vLLM, just at
8192 not 1056). ≥8192 is ~linear in chunk count (16384 = 2×, 32000 = 4×). Below 8192:
smooth, **no inner sawtooth** — the vLLM-E8 sub-block teeth (every 1056) are absent.
Raise `--chunked-prefill-size` to push the edge out (cost: bigger prefill batch).

## E-SG3 — fine 5k–20k sweep, C=1 (intra-band rise + per-chunk steps)
`ttft_sweep.py --lengths 5000,6144,7168,8192,9216,10240,12288,14336,16384,17408,
18432,20000 --concurrency 1 --n 10 --warm 3`. Resolve the band structure E-SG2 only
sampled coarsely.

| L | p50 ms | p90 | chunks | 2nd/3rd-chunk fill | band |
|---:|---:|---:|---:|---|---|
| 5000  | 98.4  | 98.9  | 1 | — | band-1 |
| 6144  | 115.1 | 115.4 | 1 | — | rising |
| 7168  | 130.5 | 136.3 | 1 | — | ~16 µs/tok |
| 8192  | 150.9 | 151.4 | 1 | chunk-1 full | edge |
| 9216  | 233.7 | 234.0 | 2 | +1024 | **+83 ms step** |
| 10240 | 234.0 | 235.9 | 2 | +2048 | band-2 flat |
| 12288 | 235.2 | 241.2 | 2 | +4096 | (open chunk cheap) |
| 14336 | 270.3 | 271.1 | 2 | +6144 | rising |
| 16384 | 305.3 | 305.6 | 2 | chunk-2 full | edge |
| 17408 | 389.0 | 390.1 | 3 | +1024 | **+84 ms step** |
| 18432 | 389.6 | 390.8 | 3 | +2048 | band-3 flat |
| 20000 | 396.0 | 399.3 | 3 | +3616 | |

Structure = staircase, not teeth. **Within** an 8192 band TTFT rises smoothly with the
open chunk's fill (band-1: 98→151 over 5k→8.2k ≈ 16 µs/tok marginal; band-2: flat ~234
until the 2nd chunk passes ~half, then 234→305); **across** a band the +8192th token
adds one full 40-layer pass = a near-fixed **~+83 ms step** (8192→9216, 16384→17408
both +83/84, independent of how full the new chunk is). p90≈p50 throughout (real).
So long-context TTFT(L) ≈ ceil(L/8192)·(~83 ms pass overhead) + (open-chunk compute).
Still **no 1056-style inner sawtooth** anywhere — the only discontinuities are the two
chunk edges. (vLLM E5/E8 had both: chunk steps at 8192 *and* sub-block teeth at 1056.)

## Cross-engine summary (H100 80GB, Qwen3.5-MoE FP8, C=1, 3k–5k)
| | vLLM stock (E8) | vLLM tuned (E9) | **SGLang default** |
|---|---|---|---|
| TTFT 3k–5k | sawtooth 94–179 ms | flat 88–103 ms | **flat 95–98 ms** |
| sawtooth | yes (≤~1.8×) | removed | **none** |
| attn block / page | 1056 (arch-derived) | 8192 | **page_size=1** |
| KV capacity | 1.39M tok | 269k tok | **1.006M tok** |
| mamba allocator | unified (mamba==attn page) | unified → 6.76× slot bloat | **separate (287 slots, 17.3 GB)** |
| concurrency knob | — | `--max-num-seqs 8` (forced) | `max_running_requests=95` |
| tuning to get flat TTFT | n/a | block + seqs cap | **none** |
| stand-up | `pip` + 1 cmd | same | cu130 kernel wrangling (E-SG0) |

The headline: vLLM made you **trade** flat TTFT against KV capacity (E9's block=8192
fixes the sawtooth but collapses 1.39M→269k tok via the unified mamba/attn page).
SGLang gives flat TTFT **and** ~1M-tok capacity **and** ~95-way concurrency out of the
box, because it never couples mamba state size to the attention page and never block-
quantizes KV. Cost is paid up front in install friction, not in serving.

## E-SG4 — thinking vs instruct mode, chat endpoint (spot check)
Per model card §4.3: Qwen3.6 defaults to **Thinking** mode; `--reasoning-parser qwen3`
splits `<think>` into `reasoning_content`; pass `chat_template_kwargs={"enable_thinking":
false}` per-request for **Instruct**. Switched off the raw-token path → real text via
`/v1/chat/completions` (`chat_mode_bench.py`, snail-pole word problem, C=1, temp 0,
max_tokens 4096, median of 3).

| mode | TTFT ms | 1st-content ms | ITL ms/tok | out_tok | reason_ch | cont_ch | wall ms |
|---|---:|---:|---:|---:|---:|---:|---:|
| thinking (default) | 98.7 | **10194.7** | 5.39 | 1880 | 5108 | 8 | **10224** |
| instruct (`enable_thinking:false`) | 103.7 | 103.7 | 5.38 | 690 | 0 | 1783 | **3814** |

- Parser works: thinking → `reasoning_content` populated, `content` empty until `<think>`
  closes; instruct → `reasoning_content: None`, direct answer. (prompt_tokens 52 vs 54 —
  template injects 2 extra tokens for the no-think path.)
- **TTFT mode-agnostic** (99 vs 104 ms) — confirms E-SG1/E-SG2 prefill numbers don't
  depend on mode; the parser is output-side only.
- **ITL mode-agnostic** (5.39 vs 5.38 ms/tok) — same per-token forward pass.
- Difference is pure **token volume**: thinking emits ~2.7× tokens (1880 vs 690) → wall
  10.2 s vs 3.8 s, and first *content* token lands at **10.2 s** (after the whole think
  block streams) vs at TTFT for instruct. UX cost of default-on thinking is large here.
- Cross-engine flag: SGLang decode **~5.4 ms/tok** vs vLLM E4 steady-state **~3.4–3.9
  ms/tok**. Not apples-to-apples (E4 = early-token gaps, short ctx; here = mean ITL over
  a long gen), but SGLang force-disables overlap schedule (`mamba no_buffer`) — likely
  leaves decode on the table. Needs a matched ITL run to confirm (see TODO).

## E-SG5 — `chunked_prefill_size=24576` moves the step out (TTFT knob)
Relaunch identical except `--chunked-prefill-size 24576` (was 8192). Same C=1 raw-token
TTFT sweep. Q: does the staircase edge follow the chunk size? (derived: chunked_prefill_
size=24576, max_prefill_tokens still 16384, max_total_num_tokens=1006799 unchanged.)

| L | 8k-chunk p50 | 24k-chunk p50 | passes (24k) |
|---:|---:|---:|---:|
| 2000  | ~89   | 93.5  | 1 |
| 3000  | ~95   | 102.8 | 1 |
| 5000  | 98.4  | 101.0 | 1 |
| 8192  | 150.9 | **147.0** | 1 (no step) |
| 12288 | 235.2 | **218.0** | 1 |
| 16384 | 305.3 | **291.4** | 1 (no step) |
| 17408 | 389.0 | 310.4 | 1 |
| 20000 | 396.0 | **357.7** | 1 |
| 24576 | ~450  | 447.9 | 1 (chunk full) |
| 25000 | —     | **530.1** | 2 ← step moved here |
| 28000 | 537.9 | 537.9 | 2 |
| 32000 | 649.1 | 625.5 | 2 |

Edge follows the knob: with 24576, everything ≤24576 is ONE smooth single-pass curve —
the 8192 and 16384 steps are gone. TTFT(L) = ~93 ms (2k) → ~448 ms (24576), rising
~18 µs/tok (matches the within-chunk slope from E-SG3). First step now at 24576→25000
(+82 ms, the 2nd pass). So bigger chunk = **strictly lower TTFT** in the 8k–24k range
(20k: 358 vs 396; 16384: 291 vs 305) because it removes the extra-pass step overhead.
`max_prefill_tokens=16384` did NOT clamp the single-request chunk (no step at 16384) —
it bounds the cross-request batch, not one prompt's chunk.
Trade (not TTFT): a 24k single-chunk prefill is a big forward batch → monopolizes a pass,
hurting other requests' TTFT under concurrency. Free win at C=1; revisit under load.

## E-SG6 — kernel-level prefill profile, L=4200 (vs vLLM E10)
`sgl_prof.py --len 4200 --decode 1 --warm 4` — drives SGLang's torch profiler
(`/start_profile {output_dir, activities:[CPU,GPU], record_shapes}` → 1 prefill
max_tokens=1 → `/stop_profile`), buckets device-kernel `dur` by name. Same method as
vLLM E10/prof_prefill.py. (`profile_by_stage:true` crashes the server — SGLang bug,
`profiler_prefill_ct` None += int — avoided.)

| bucket | vLLM E10 ms | SGLang ms | note |
|---|--:|--:|---|
| MoE expert GEMM | 23.73 | **21.87** | SGLang default ≈ vLLM *forced-DeepGEMM* (E12=21.7) |
| gated-deltanet scan/conv | 9.61 | **14.05** | TritonGDNKernel ~4.4 ms *slower* than vLLM chunked DeltaRule |
| dense proj GEMM | 11.19 | 11.70 | = |
| rmsnorm/elementwise/rope | 9.73 | 11.69 | ~= |
| FP8 quant | 5.13 | 4.45 | ~= |
| full attn | 2.10 | 3.94 | fa3 > vLLM fmha (both small) |
| routing reduce/topk | 2.92 | 0.91 | SGLang cheaper |
| **Σ GPU busy** | **66.35** | **68.70** | within 3.5% |

Same FLOPs → same ~67 ms GPU-busy. Composition trades off: SGLang wins MoE (already at
DeepGEMM level, no tuning), loses gated-deltanet (Triton GDN 14.0 vs 9.6). Net wash.
Profiler-on wall 183 ms (instrumentation ~1.9×); clean TTFT@4200 ~95 ms → ~26 ms launch
bubble (vLLM E10 ~29 ms). The 30%/~20 ms "overhead" vLLM flagged (quant+route+norm) is
present here too (quant 4.5 + norm/elem 11.7 + routing 0.9 ≈ 17 ms).

## E-SG7 — e2e profile: prefill + 32 decode, L=4200
`sgl_prof.py --len 4200 --decode 33`. One trace over prefill+32 decode passes; decode/step
= (e2e − prefill)/32. Profiler-on (~1.27× inflated); clean e2e ~268 ms (95 TTFT + 32×5.4).

| bucket | e2e ms | prefill ms | decode/step ms |
|---|--:|--:|--:|
| dense proj GEMM | 96.64 | 11.70 | **2.65** |
| rmsnorm/elementwise/rope | 71.45 | 11.69 | **1.87** |
| MoE expert GEMM | 53.77 | 21.87 | 1.00 |
| FP8 quant | 16.70 | 4.45 | 0.38 |
| full attn (fa3) | 15.87 | 3.94 | 0.37 |
| routing | 9.23 | 0.91 | 0.26 |
| gated-deltanet | 21.74 | 14.05 | 0.24 |
| **Σ GPU busy** | **287.9** | **68.7** | **~6.85** |

Profile **inverts** prefill→decode: prefill is compute-bound (MoE 32% + GDN 20%); decode
(batch=1) is **memory/launch-bound** — dense-proj GEMV 39% + norm/rope/elementwise 27%,
while MoE/attn/GDN go tiny (no batch to amortize; GDN's O(1) recurrence = 0.24 ms/step).
→ decode = 40 layers × many small kernels = launch-overhead dominated = exactly what an
**overlap scheduler hides**. SGLang force-disables overlap (`mamba no_buffer`), so this is
the concrete lever behind the E-SG4 ITL gap (~5.4 vs vLLM ~3.4 ms/tok). Tools committed:
`sgl_prof.py`.
